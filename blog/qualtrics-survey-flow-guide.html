Qualtrics Survey Flow: Complete Guide for Advanced Users (2026)

Arun Raj•July 18, 2026•3 min read•Glossary
Definition

Qualtrics Survey Flow is the visual control centre for how a survey runs - it determines the order and conditions under which question blocks, embedded data, branching logic, randomisers, and end-of-survey elements execute. Mastering Survey Flow is essential for building surveys that go beyond simple linear question sequences.

Question Blocks

Blocks are the fundamental units of Survey Flow. Every question in Qualtrics lives inside a block. By default, a new survey has one block. Add blocks to organise questions into logical groups: an intro block, a screening block, separate content blocks for different survey sections, and a closing block. In Survey Flow, blocks appear in the order they will be presented - drag them to reorder. Questions within a block appear in the order set in the survey editor, subject to display and skip logic.

Blocks are the unit at which block-level randomisation and block display logic operate. Set block display logic from the block header options - show or hide an entire block based on embedded data, prior answers, or quota status without setting conditions on every individual question.

Embedded Data Elements

Embedded data elements in Survey Flow define the fields that travel with each response throughout the survey. Place them at the top of Survey Flow (before any question blocks) so their values are available to display logic and piped text from the first question. Each embedded data element specifies a field name and where the value comes from: URL parameter, XM Directory contact attribute, static default value, or a value set conditionally by branch logic.

After the survey, embedded data values appear in the response data export alongside question answers - enabling segmentation and filtering in dashboards without joining to external data files. See the complete embedded data guide for setup instructions.

Branch Logic

Branch Logic in Survey Flow routes respondents to different blocks based on conditions - more powerful than skip logic in question editors because it operates at the block level and supports embedded data conditions, quota conditions, and multi-condition AND/OR logic. Add a Branch element, define the condition, then drag the blocks that should appear for respondents meeting that condition inside the branch.

For complex routing - multiple audience segments each seeing different question sets - nested branches create the logical structure. Survey Flow's visual layout makes the branching architecture easier to audit than question-level skip logic scattered across many individual questions.

Randomiser

The Randomiser element randomly selects a subset of blocks from a defined pool and presents them to each respondent. Use for sequential monadic concept testing (show each respondent one of five concepts), for A/B testing survey instrument variants, or for random block rotation in long surveys. Configure the number of blocks to present to each respondent and whether the selection should be evenly distributed across respondents (balanced randomisation) or truly random.

End of Survey

The End of Survey element controls what happens when a respondent completes the survey or is terminated early. Configure it to show a custom completion message, redirect to a URL, or (for panel surveys) redirect to the panel provider's completion link. For surveys with multiple end points - full completes, screenouts, and over-quota terminations - add multiple End of Survey elements at different points in Survey Flow, each configured with the appropriate message and redirect for that outcome.

Authenticator

The Authenticator element restricts survey access to authenticated respondents. It can authenticate against Qualtrics' panel (SSO), a custom contact list, or an external web service. Used for surveys requiring login (employee surveys that should only be accessible to current employees, client surveys restricted to account holders) or for studies requiring pre-screening against an eligibility list.

Web Service

The Web Service element calls an external API during the survey and stores the response as embedded data. Use to look up respondent-specific information at survey runtime - pulling account details, order history, or eligibility status from a CRM or data warehouse - without embedding that data in the survey distribution link. The web service call happens mid-survey, triggered by Survey Flow reaching the element.

Survey Flow Best Practices

Always put Embedded Data elements first. Place all embedded data elements at the very top of Survey Flow, before any question blocks. This ensures field values are set before any question tries to reference them in piped text or display logic.

Name your blocks descriptively. Default block names (Block 1, Block 2) make Survey Flow hard to read for complex surveys. Rename blocks to reflect their content: "Screener," "Product Battery," "NPS," "Demographic Closeout." This saves time when debugging logic and auditing survey structure before launch.

Use Block Display Logic for efficiency. If multiple questions in a block share the same display condition, set block display logic on the block rather than question display logic on each question individually. This reduces the number of logic conditions to maintain and makes the survey easier to audit.

Test every branch path before launch. Use Qualtrics' Preview Survey feature to test every branch logic path. For each branch condition, verify that the correct blocks appear and that end-of-survey redirects fire correctly. Untested branch logic is the most common cause of mid-field survey errors.

Frequently Asked Questions

What is Qualtrics Survey Flow?+

Survey Flow is the visual control centre for how a Qualtrics survey runs. It defines the order and conditions under which question blocks, embedded data, branch logic, randomisers, and end-of-survey elements execute. Access it from the Survey tab by clicking 'Survey Flow' in the left sidebar.

What is the difference between Survey Flow Branch Logic and question Skip Logic?+

Survey Flow Branch Logic routes entire blocks of questions based on conditions - supporting embedded data values, quotas, and multi-condition AND/OR logic at the block level. Question Skip Logic routes respondents forward past questions within a block based on a single question's answer. Branch Logic is more powerful and flexible; Skip Logic is better for simple forward-jump scenarios.

Where should I place Embedded Data elements in Survey Flow?+

Always place Embedded Data elements at the very top of Survey Flow, before any question blocks. This ensures the embedded data field values are set before any question in the survey attempts to reference them in display logic conditions or piped text.

Can I use Qualtrics Survey Flow to randomise which concepts respondents see?+

Yes. Add a Randomiser element in Survey Flow. Place each concept block inside the Randomiser. Configure how many blocks each respondent sees (e.g. 1 of 5 concepts) and whether distribution should be balanced across respondents. This is the standard setup for sequential monadic concept tests.
